## 시각·동선 변경

- 어두운 공통 헤더, 밝은 작업 영역, 단일 청록색 행동 버튼. 사용 가능한 폭에 따라 상품 가격·구성·행동을 함께 배치한다.
- Markets 첫 화면에서 상품과 투자 미개방 상태, 상세 진입 버튼이 보인다. 모바일에는 일관된 하단 메뉴를 쓴다.
- 상품은 실제 NAV 이력 → 구성 종목 → 조건 순서다. 임의의 수익률·TVL·이용자 수는 생성하지 않는다.
- 보유 상세는 모바일에서 내 가치·수량·추가 행동이 먼저 보인다. 보유가 완료되지 않은 금액은 총자산에 합치지 않는 상태를 시안에 표현했다.
- Transparency는 결과 요약과 구성 근거를 먼저 보여준다. 계산·해시·원문·발행 이력은 펼쳐 볼 수 있다. 가격 변경 실험은 Lab으로 옮겼다.
- 구성 띠와 자산 행의 선택·기여 금액이 연결된다. 짧은 진입/선택/주문 검토 전환과 누름 반응을 적용하고, 움직임 줄이기 설정에서는 애니메이션·전환을 제거한다.

## 검수 근거

- 전체 기존·신규 자동 검사 82개 통과. 최종 화면 변경 후 타입검사·운영 빌드와 관련 12개 검사를 다시 수행했다.
- 서버 렌더링 단계의 메뉴·활성 항목, 옛 경로 이동, 예시 데이터 운영 차단, 기존 Lab/문서 접근을 검사했다.
- 실제 구성은 표시 중인 기록과 NAV·시각이 맞는 문서로만 구성한다. 기록 차트는 confirmed 발행 이력과 확인된 체인 스냅샷으로 만들고 초 단위 중복을 제거한다.
- 브라우저에서 공개 RPC 직접 읽기, 원문 해시, 재계산 NAV가 모두 일치했다. 관측한 기록은 2026-09-24 08:10 UTC이며 시장 읽기에서는 이후 08:15 UTC 기록도 표시됐다. 이 관측을 장기간 무장애 보증으로 해석하지 않는다.
- 360/390 모바일, 768 태블릿, 1440 데스크톱, 2560 큰 화면의 대표 페이지를 확인했다. 모바일 메뉴/지갑 줄바꿈, 태블릿 보유 버튼, 보유 상세 우선순위를 수정했다. 확인한 화면에서 가로 넘침은 없었다.
- 예시 주문 잔액 초과 시 입력 오류와 검토 차단, 250 USDC 입력의 검토 → 진행 → 완료 수량 일치, 회복 상태, Portfolio → 보유 상세를 확인했다.
- 조회 실패를 반환하는 로컬 프리뷰에서 대시 값과 재시도 안내가 유지됐다. 실패를 0원이나 성공으로 표시하지 않는다.
- 차트/기록 표 전환, 키보드로 기록 선택, 구성 종목 선택을 브라우저에서 확인했다.
- 새 범위에 대한 사람 대상 사용성 평가, 전체 화면 400% 확대 검사, 실제 지갑 승인·계정 전환, 실거래·보관·회수는 완료했다고 주장하지 않는다.
